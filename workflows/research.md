# ldgr-research workflow

You are running research, not construction. The unit of progress is a resolved
hypothesis, not a completed task.

## Choose the mode first

**If you were given a complete set of experiments**, execute them as specified.
Schedule them as work items, run them, and record results. Do not redesign the
study.

**If the question is open-ended**, run the hypothesis-driven cycle below. This
is the default.

## The cycle

### 1. Preregister the hypothesis

State the hypothesis before you build anything, and record it through the
extended research commands. A preregistered hypothesis names:

- what you expect to be true;
- what result would confirm it;
- what result would falsify it.

Write the falsification condition down *first*. A hypothesis that no observable
outcome could refute is not a hypothesis, and discovering that after the fact
wastes the whole cycle.

### 2. Build the experiment

Construct the smallest experiment that can actually discriminate between the
hypothesis holding and failing. Record the setup as an artifact so the run can
be reproduced without reconstructing it from conversation.

### 3. Run it

Execute the experiment and capture the results as evidence attached to the run.
Record what happened, including runs that failed to execute cleanly — a broken
experiment is a result about the experiment.

### 4. Interpret

Record the interpretation separately from the raw results. State plainly whether
the hypothesis was confirmed, falsified, or left unresolved. Inconclusive is a
legitimate outcome; report it as inconclusive rather than stretching the data
into a conclusion it does not support.

### 5. Decide the next step

Choose where the research goes next and record the decision with its rationale.

**Select broad branches to explore. Do not map the problem space slice by
slice.** Exhaustively characterizing one narrow region is expensive and usually
tells you less than sampling several distinct directions. Prefer the next
branch that could most change your understanding over the next increment that
merely refines it.

## Standing rules

- Claims stay linked to the evidence that supports them. A fact with no
  traceable support is an assumption.
- Record disconfirming results with the same care as confirming ones. The
  research record is only useful if it can be trusted when it disagrees with
  you.
- One cycle is one experiment. New questions become queued research options, not
  detours inside the current run.
